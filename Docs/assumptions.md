# Trust Assumptions

Security engineering requires explicit definitions of what is trusted. 

## Trusted Components
1.  **PostgreSQL Database**: We assume the database file system is secure and the connection is encrypted (SSL mode in production).
2.  **Redis Cache**: We assume the Redis instance is isolated within the internal network and not exposed to the public internet.
3.  **Authentication Provider**: We assume the JWT signing key (secret) is kept confidential and not committed to version control.

## Trusted External Services
1.  **Google Safe Browsing API**: We trust their verdicts to be accurate (low false positive rate).
2.  **VirusTotal**: We trust their aggregation engine.
3.  **OpenAI (Optional)**: We trust the API to return text that does not contain executable malicious payloads (though we still treat the text as untrusted).

## Untrusted Components (Zero Trust)
1.  **Deployment Environment**: We assume the host OS could be compromised. We run with least-privilege users.
2.  **Client-Side Code**: We never trust validation performed in the browser. All checks must be repeated on the server.
3.  **Time**: We do not trust the client's system clock. Timestamps are generated by the server.
